[[Современные операционные системы (Windows)]]

Каталог — это иерархическая структура, которая хранит сведения о объектах в сети. Служба каталогов, например службы домен Active Directory (AD DS), предоставляет методы хранения данных каталога и предоставления этих данных сетевым пользователям и администраторам. Например, AD DS хранит сведения о учетных записях пользователей, таких как имена, пароли, номера телефонов и т. д. AD DS также предоставляет возможность авторизованным пользователям в той же сети получить доступ к этой информации.

AD DS также включает:

- Набор правил, **схема**, которая определяет классы объектов и атрибутов, содержащихся в каталоге, ограничения и ограничения экземпляров этих объектов, а также формат их имен. Дополнительные сведения о схеме см. в разделе ["Схема](https://learn.microsoft.com/ru-ru/previous-versions/windows/it-pro/windows-server-2003/cc756876\(v=ws.10\))".
    
- **Глобальный каталог**, содержащий сведения о каждом объекте в каталоге. Пользователи и администраторы могут использовать каталог для поиска сведений о каталоге независимо от домена каталога, который фактически содержит данные. Дополнительные сведения о глобальном каталоге см. в [глобальном каталоге](https://learn.microsoft.com/ru-ru/windows/win32/ad/global-catalog).
    
- **Механизм** запроса и индекса, чтобы объекты и их свойства могли быть опубликованы и найдены сетевыми пользователями или приложениями. Дополнительные сведения о запросе каталога см. в разделе [Поиск в службах доменов Active Directory](https://learn.microsoft.com/ru-ru/windows/win32/ad/searching-in-active-directory-domain-services).
    
- **Служба репликации**, которая распределяет данные каталога по сети. Все контроллеры домена в домене участвуют в репликации и содержат полную копию всех сведений о каталоге для своего домена. Любые изменения данных каталога реплицируются в домене на все контроллеры домена. Дополнительные сведения о репликации AD DS см. в [концепциях репликации Active Directory](https://learn.microsoft.com/ru-ru/windows-server/identity/ad-ds/get-started/replication/active-directory-replication-concepts).

**Контроллер домена (Domain Controller)** это сервер под управлением Windows Server с установленной ролью AD DS. Хранит базу данных каталога (NTDS.dit), отвечает за проверку подлинности и авторизацию пользователей/компьютеров, репликацию и хранилище политик (SYSVOL). 
**DNS-сервер (интегрированный с AD DS)** это служба разрешения имен. Используется клиентами для обнаружения служб домена (через специальные SRV-записи вида `_ldap._tcp.dc._msdcs.<Domain>`).
**SYSVOL** это специальная общая папка на контроллере домена, содержащая файлы групповых политик (GPO) и сценарии входа/выхода.
**Организационная единица (OU)** это контейнер внутри домена для группировки объектов (пользователи, ПК, группы).

**SID** — это глобально уникальный неизменяемый идентификатор (строка вида S-1-5-21-...-1001), который генерируется системой в момент создания объекта (пользователя, группы, компьютера).
В списках контроля доступа (ACL) к файлам, папкам и ресурсам хранятся именно SID, а не текстовые имена. Так как переименование меняет только атрибуты sAMAccountName, cn или displayName, а SID остается прежним, доступ к ресурсам не прерывается.

Active Directory использует **многомастерную репликацию (Multi-Master Replication)**. Изменения могут вноситься на любом доступном DC. Каждое изменение объекта на DC сопровождается инкрементом локального номера последовательного обновления — **USN (Update Sequence Number)**.
DC-источник уведомляет партнеров по репликации через механизм Change Notification (по умолчанию в течение 15 секунд). 
DC-приемник запрашивает изменения по протоколу RPC/IP (DRSUAPI), сравнивает полученные векторы обновлений (Up-To-Dateness Vector) со своими и применяет недостающие записи.

Хотя AD DS — это многомастерная система, некоторые системные операции принципиально не могут выполняться параллельно на разных серверах, так как это неминуемо приведет к критическим конфликтам, которые алгоритмы репликации не смогут автоматически разрешить. Для таких операций выделяется единственный контроллер, обладающий исключительным правом их выполнения (FSMO/Single-Master). 
**Роль Schema Master (Хозяин схемы):** Отвечает за внесение изменений в структуру классов и атрибутов каталога всего леса (например, при развертывании Microsoft Exchange или обновлении версии схемы Windows Server).
**Другой наглядный пример — RID Master:** Выдает пулы относительных идентификаторов (RID) контроллерам домена. Если бы каждый DC генерировал RID самостоятельно, возник бы риск создания двух разных объектов с одинаковым SID.
