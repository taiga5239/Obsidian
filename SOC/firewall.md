==🔴Межсетевой экран== предназначен для проверки входящего и исходящего трафика сети или цифрового устройства. 

==🔴***Stateless firewall***==

Этот тип межсетевого экрана работает на 3-м и 4-м уровнях модели OSI и функционирует исключительно путем фильтрации данных на основе заранее определенных правил, не принимая во внимание состояние предыдущих соединений.

Это означает, что он будет сопоставлять каждый пакет с правилами независимо от того, является ли он частью легитимного соединения. Он не хранит информацию о состоянии предыдущих соединений для принятия решений в отношении будущих пакетов. Благодаря этому такие межсетевые экраны могут обрабатывать пакеты быстро. Однако они не могут применять сложные политики к данным, основанные на их связи с предыдущими соединениями.

***==🔴Stateful Inspection firewall==***

Этот тип межсетевых экранов выходит за рамки фильтрации пакетов по заранее определенным правилам. Он также отслеживает предыдущие соединения и сохраняет их в таблице состояний. Это добавляет еще один уровень безопасности, проверяя пакеты на основе их истории соединений. Межсетевые экраны с сохранением состояния работают на 3-м и 4-м уровнях модели OSI. 

***==🔴Proxy Firewalls==***

Прокси-межсетевые экраны, или шлюзы прикладного уровня, выступают в качестве посредников между частной сетью и Интернетом и работают на 7-м уровне модели OSI. Они также проверяют содержимое всех пакетов. Запросы, отправляемые пользователями в сети, пересылаются этим прокси-сервером после проверки и маскировки их собственным IP-адресом для обеспечения анонимности внутренних IP-адресов. К этим межсетевым экранам можно применять политики фильтрации контента, позволяющие разрешать/запрещать входящий и исходящий трафик в зависимости от его содержимого.

***==🔴Next-Generation Firewall (NGFW)==***

Это самый продвинутый тип межсетевого экрана, работающий на уровнях с 3 по 7 модели OSI, предлагающий глубокий анализ пакетов и другие функции, повышающие безопасность входящего и исходящего сетевого трафика. Он имеет систему предотвращения вторжений, которая блокирует вредоносные действия в режиме реального времени. Он предлагает эвристический анализ, анализируя закономерности атак и мгновенно блокируя их до того, как они достигнут сети. Межсетевые экраны нового поколения (NGFW) поддерживают SSL/TLS - возможности расшифровки, которые проверяют пакеты после их расшифровки и сопоставляют данные с потоками информации об угрозах для принятия эффективных решений.

Основные компоненты правила брандмауэра описаны ниже:

- **Адрес источника:** IP-адрес машины, с которой будет осуществляться трафик.
- **Адрес назначения:** IP-адрес машины, которая будет получать данные.
- **Порт:** Номер порта, используемого для передачи данных.
- **Протокол:** Протокол, который будет использоваться во время обмена данными.
- **Действие:**  Здесь определяются действия, которые будут предприняты при обнаружении любого трафика такого рода.
- **Направление:** Это поле определяет, к какому типу трафика применимо правило — входящему или исходящему.

==🔵Netfilter== — это встроенная в операционную систему Linux платформа с основными функциями межсетевого экрана, включая фильтрацию пакетов, NAT и отслеживание соединений. Эта платформа служит основой для различных утилит межсетевого экрана, доступных в Linux для управления сетевым трафиком.

Распространенные утилиты межсетевого экрана, использующие эту платформу:

- **iptables:** Это наиболее широко используемая утилита во многих дистрибутивах Linux. Она использует фреймворк Netfilter, который предоставляет различные функции для управления сетевым трафиком.
- **nftables:** Это преемник утилиты «iptables» с расширенными возможностями фильтрации пакетов и NAT. Он также основан на фреймворке Netfilter.
- **firewalld:** Эта утилита также работает на основе платформы Netfilter и имеет предопределенные наборы правил. Она работает иначе, чем другие, и поставляется с различными предварительно созданными конфигурациями сетевых зон.

==🔵ufw (Uncomplicated Firewall)==, как следует из названия, устраняет сложности, связанные с созданием правил в сложном синтаксисе в «iptables» (или его преемнике), предоставляя более простой интерфейс

В основном, любые необходимые вам правила в «iptables» можно определить с помощью простых команд через ufw, которые затем будут представлять собой настройку нужных правил в «iptables».

```
user@ubuntu:~$ sudo ufw default allow outgoing
Default outgoing policy changed to 'allow'
(be sure to update your rules accordingly)     
```

```
user@ubuntu:~$ sudo ufw deny 22/tcp
Rule added
Rule added (v6)   
```

Чтобы вывести список всех активных правил в нумерованном порядке, можно использовать следующую команду:
```
user@ubuntu:~$ sudo ufw status numbered
     To                         Action      From
     --                         ------      ----
[ 1] 22/tcp                     DENY IN     Anywhere                  
[ 2] 22/tcp (v6)                DENY IN     Anywhere (v6)    
```

Для удаления правила выполните следующую команду, указав номер удаляемого правила:
```
user@ubuntu:~$ sudo ufw delete 2
Deleting:
 deny 22/tcp
Proceed with operation (y|n)? y
Rule deleted (v6)  
```
