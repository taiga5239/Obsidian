**Два подхода к архитектуре приложений**

***Монолит***
	В монолите все компоненты программы — от авторизации до обработки платежей — находятся в одном проекте, компилируются в один файл и запускаются на одном сервере. Подходит стартапам, проектам на стадии MVP (минимально жизнеспособный продукт), небольшим командам и приложениям с предсказуемой нагрузкой.

*Основные характеристики и вызовы* 
- Проще тестирование (все в одном месте) 
- Легче отладка и поиск ошибок 
- Меньше сетевых взаимодействий
*Недостатки и риски* 
- Сложность изменений (все связано) 
- Риск полного отказа системы 
- Ограничения масштабирования

***Микросервисы***
	Приложение разбивается на модули, которые общаются друг с другом по сети (через REST API, gRPC или брокеры сообщений вроде Kafka/RabbitMQ). У каждого сервиса своя зона ответственности и, как правило, своя база данных. Подходит крупным enterprise-проектам, распределенным командам (когда над разными фичами работают отдельные группы) и системам с высокими требованиями к масштабируемости.

*Децентрализованный подход* 
- Независимое тестирование компонентов 
- Быстрое развертывание изменений 
- Устойчивость к отдельным сбоям
*Сложности и вызовы* 
- Сложность интеграционного тестирования 
- Больше точек отказа 
- Сложнее отслеживать данные

**АРІ**: ЯЗЫК ОБЩЕНИЯ МЕЖДУ ПРОГРАММАМИ

**API** (Application Programming Interface) - это набор правил, который позволяет программам взаимодействовать друг с другом.

*Ключевые элементы* 
- Методы (что можно сделать)
- Данные на входе (запрос) 
- Данные на выходе (ответ) 
- Обработка ошибок

**"СЛОВАРЬ" АРІ: ОСНОВНЫЕ КОМАНДЫ**

**GET - Получить данные** 
	*Чтение информации* 
	Пример: получить список пользователей
**POST - Создать новое**
	 *Добавление новых данных* 
	 Пример: создать нового пользователя 
**PUT - Обновить всё** 
	 *Полное обновление объекта* 
	 Пример: изменить данные пользователя 
**PATCH - Частичное обновление** 
	 *Изменить только указанные поля* 
	 Пример: сменить еmail пользователя
**DELETE - Удалить** 
	 *Удаление данных* 
	 Пример: удалить пользователя

**Что говорит сервер? Читаем коды ответов**
***1xx - Информационные***
- 100 Continue - продолжаем
- 101 Switching Protocols
***2xx - Успех***
- 200 OK - все хорошо
- 201 Created - создано успешно
- 204 No Content - нет содержимого
***5xx - Ошибки сервера***
- 500 Internal Server Error
- 502 Bad Gateway
- 503 Service Unavailable
***3xx - Перенаправление***
- 301 Moved Permanently
- 304 Not Modified
***4xx - Ошибки клиента***
- 400 Bad Request - неверный запрос
- 401 Unauthorized - не авторизован
- 403 Forbidden - доступ запрещен
- 404 Not Found - не найдено

**JSON** (англ. JavaScript Object Notation) — текстовый формат обмена данными, основанный на *JavaScript*. Но при этом формат независим от JS и может использоваться в любом языке программирования. 
JSON используется в *REST API*.

В качестве значений в JSON могут быть использованы: 
- JSON-объект 
- Массив 
- Число (целое или вещественное) 
- Литералы true (логическое значение «истина»), false (логическое значение «ложь») и null 
- Строка 
Если говорить про REST API, то обычно вы будете отправлять / получать именно json-объекты. Разберем массивы и объекты.

JSON-объект — это неупорядоченное множество пар «ключ:значение», заключённое в фигурные скобки «{}». 
Ключ описывается строкой, между ним и значением стоит символ «:». Пары ключ-значение отделяются друг от друга запятыми. 
Ключ — это название параметра, который мы передаем серверу. 
Он служит маркером для принимающей запрос системы: «смотри, здесь у меня значение такого-то параметра!». 
Значения ключа могут быть любыми: 
- число 
- строка 
- массив 
- другой объект

Массив — это просто набор значений, разделенных запятыми. Находится внутри квадратных скобок \[]. 
А вот внутри него может быть все, что угодно.
