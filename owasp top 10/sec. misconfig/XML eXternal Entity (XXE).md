Внедрение внешних сущностей (XML External Entity injection) — это тип уязвимости безопасности, использующий уязвимости во входных XML-данных приложения. Оно происходит, когда приложение принимает входные XML-данные, содержащие ссылки на внешние сущности внутри самого XML. Злоумышленники могут использовать эту уязвимость для раскрытия локальных файлов, выполнения запросов на стороне сервера или выполнения удаленного кода.


XML (Extensible Markup Language) — это язык разметки, производный от SGML (Standard Generalized Markup Language), который является тем же стандартом, на котором основан HTML. XML обычно используется приложениями для хранения и передачи данных в формате, который одновременно удобочитаем и машиночитаем. Это гибкий и широко используемый формат для обмена данными между различными системами и приложениями. XML состоит из элементов, атрибутов и символьных данных, которые используются для представления данных структурированным и организованным способом.

XML-элементы представляются тегами, которые заключаются в угловые скобки (<>). Теги обычно располагаются парами: открывающий тег предшествует содержимому, а закрывающий тег следует за содержимым. Например:
```
<?xml version="1.0" encoding="UTF-8"?>
<user id="1">
   <name>John</name>
   <age>30</age>
   <address>
      <street>123 Main St</street>
      <city>Anytown</city>
   </address>
</user>
```

==🔴XSLT (Extensible Stylesheet Language Transformations)== — это язык, используемый для преобразования и форматирования XML-документов. Хотя XSLT в основном используется для преобразования и форматирования данных, он также имеет важное значение для атак XXE (XML External Entities).

XSLT может использоваться для осуществления XXE-атак несколькими способами:

- Извлечение данных : XSLT можно использовать для извлечения конфиденциальных данных из XML-документа, которые затем могут быть использованы в атаке XXE. Например, таблица стилей XSLT может извлечь учетные данные пользователя или другую конфиденциальную информацию из XML-файла.
- Расширение сущностей : XSLT может расширять сущности, определенные в XML-документе, включая внешние сущности. Это может позволить злоумышленнику внедрять вредоносные сущности, что приводит к уязвимости XXE.
- Манипулирование данными : XSLT позволяет манипулировать данными в XML-документе, что потенциально дает злоумышленнику возможность внедрять вредоносные данные или изменять существующие данные для использования уязвимости XXE.
- Слепая XXE-атака : XSLT может использоваться для выполнения слепых XXE-атак, при которых злоумышленник внедряет вредоносные сущности, не видя ответа сервера.

DTD (Document Type Definitions) определяют структуру и ограничения XML-документа. Они указывают допустимые элементы, атрибуты и связи между ними. DTD могут быть внутренними, внутри XML-документа, или внешними, в отдельном файле.

Назначение и использование DTD:

- Валидация : DTD-теги проверяют структуру XML, чтобы убедиться в ее соответствии определенным критериям перед обработкой, что крайне важно в средах, где целостность данных имеет первостепенное значение.
- Объявление сущностей : DTD определяют сущности, которые могут использоваться во всем XML-документе, включая внешние сущности, играющие ключевую роль в XXE-атаках.

Внутренние DTD указываются с помощью \<!DOCTYPE объявления, а внешние DTD — с помощью ключевого слова SYSTEM.
```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE config [
<!ELEMENT config (database)>
<!ELEMENT database (username, password)>
<!ELEMENT username (#PCDATA)>
<!ELEMENT password (#PCDATA)>
]>
<config>
<!-- configuration data -->
</config>
```

DTD играют решающую роль в XXE-инъекциях, поскольку могут использоваться для объявления внешних сущностей. Внешние сущности могут ссылаться на внешние файлы или URL-адреса, что может привести к внедрению вредоносных данных или кода.

==🔴Типы сущностей==
1. ***Внутренние сущности*** — это, по сути, переменные, используемые в XML-документе для определения и замены содержимого, которое может повторяться несколько раз. Они определены в DTD (Document Type Definition) и могут упростить управление повторяющейся информацией. Например:
```
<!DOCTYPE note [
<!ENTITY inf "This is a test.">
]>
<note>
        <info>&inf;</info>
</note>
```
В этом примере `&inf;` сущность заменяется своим значением везде, где она встречается в документе.

2. Внешние сущности похожи на внутренние сущности, но их содержимое ссылается извне XML-документа, например, из отдельного файла или URL-адреса. Эта особенность может быть использована в атаках XXE (XML External Entity), если XML-процессор настроен на разрешение внешних сущностей. Например:
```
<!DOCTYPE note [
<!ENTITY ext SYSTEM "http://example.com/external.dtd">
]>
<note>
        <info>&ext;</info>
</note>
```

В данном случае `&ext;` контент извлекается с указанного URL-адреса, что может представлять угрозу безопасности, если URL-адрес контролируется злоумышленником.

3. Параметрические сущности — это особые типы сущностей, используемые в DTD для определения многократно используемых структур или для включения внешних подмножеств DTD. Они особенно полезны для модульной организации DTD и для поддержки крупномасштабных XML-приложений. Например:
```
<!DOCTYPE note [
<!ENTITY % common "CDATA">
<!ELEMENT name (%common;)>
]>
<note>
        <name>John Doe</name>
</note>
```

В данном случае, `%common;` этот параметр используется в рамках DTD для определения типа данных, которые `name` должен содержать элемент.

4. Общие сущности похожи на переменные и могут быть объявлены как внутри, так и вне документа. Они используются для определения подстановок, которые могут быть использованы в теле XML-документа. В отличие от параметрических сущностей, общие сущности предназначены для использования в содержимом документа. Например:
```
<!DOCTYPE note [
<!ENTITY author "John Doe">
]>
<note>
        <writer>&author;</writer>
</note>
```

Данная сущность `&author;` представляет собой общую сущность, используемую для замены имени автора везде, где оно упоминается в документе.

5. Символьные сущности используются для представления специальных или зарезервированных символов, которые нельзя использовать напрямую в XML-документах. Эти сущности предотвращают неправильную интерпретацию синтаксиса XML парсером. Например:
```
<note>
        <text>Use &lt; to represent a less-than symbol.</text>
</note>
```

==🔴Общие рекомендации==

- Отключите обработку внешних сущностей и DTD : В качестве рекомендации следует отключить обработку внешних сущностей и DTD в ваших XML-парсерах. Большинство уязвимостей XXE возникают из-за вредоносных DTD.
	
- Используйте менее сложные форматы данных : по возможности, рассмотрите возможность использования более простых форматов данных, таких какJSONкоторые не позволяют указывать внешние сущности.
	
- Проверка входных данных в списке разрешенных : проверяйте все входящие данные на соответствие строгой схеме, определяющей ожидаемые типы данных и шаблоны.
	
- Исключайте или экранируйте символы, специфичные для XML, такие как <, >, &, ', и ". Эти символы имеют решающее значение в синтаксисе XML и могут привести к инъекционным атакам при неправильном использовании.
