[[Основы сетей]]

TCP/IP расшифровывается как Transmission Control Protocol/Internet Protocol

==🔴Протокол TCP/IP== состоит из четырех уровней и, по сути, является лишь упрощенной версией модели OSI.
*Уровни:*

- Прикладной уровень : В модели OSI прикладной, презентационный и сессионный уровни, то есть уровни 5, 6 и 7, объединены в прикладной уровень в модели TCP/IP.
- Транспортный уровень : это уровень 4.
- Интернет-уровень : это третий уровень. Сетевой уровень модели OSI называется интернет-уровнем в модели TCP/IP.
- Уровень связи : это уровень 2.

Подобно тому, как работает модель OSI, в модели TCP информация добавляется к каждому слою по мере прохождения данных (или пакета).

Одной из определяющих особенностей TCP является то, что он  **основан на установлении соединения , а это значит, что** **для**  отправки данных TCP должен установить соединение как между клиентом, так и между устройством, выступающим в роли сервера .

Благодаря этому TCP гарантирует, что любые отправленные данные будут получены на другом конце. Этот процесс называется трехсторонним рукопожатием
![[Pasted image 20261023182212.png]]

TCP-пакеты содержат различные разделы информации, известные как заголовки, которые добавляются в процессе инкапсуляции.

*Трехстороннее рукопожатие — процесс установления связи между двумя устройствами. В процессе  трехстороннего рукопожатия используется несколько специальных сообщений.
![[Pasted image 20261023183322.png]]

![[Pasted image 20261023183348.png]]

Каждым отправляемым данным присваивается случайная последовательность чисел, которая затем восстанавливается с использованием этой последовательности и увеличивается на 1. Для отправки данных в правильном порядке оба компьютера должны согласовать одну и ту же последовательность чисел. Согласование порядка происходит в три этапа:

1. SYN - Клиент: Вот мой начальный порядковый номер (ISN) для  хронизации SYN с (0)
2. SYN/ACK - Сервер: Вот мой начальный порядковый номер (ISN) для  синхронизации SYN с (5000), и я  подтверждаю получение вашего начального порядкового номера (0).
3. ACK - Клиент: Я  подтверждаю получение вашего начального порядкового номера (ISN) равным (5000), вот некоторые данные, которые представляют собой мой ISN+1 (0 + 1)

Во-первых, TCP закрывает соединение, как только одно устройство определит, что другое устройство успешно получило все данные.

Поскольку протокол TCP резервирует системные ресурсы на устройстве, рекомендуется закрывать TCP-соединения как можно скорее.

Для инициирования закрытия TCP-соединения устройство отправит другому устройству пакет "FIN". Разумеется, в случае TCP другое устройство также должно будет подтвердить получение этого пакета.

==🔴Протокол **пользовательских** **данных** (UDP)== — это ещё один протокол, используемый для передачи данных между устройствами.

В отличие от своего брата TCP, UDP — это  протокол **без сохранения состояния**  , который не требует постоянного соединения между двумя устройствами для передачи данных. Например, трехстороннее рукопожатие не происходит, и синхронизация между двумя устройствами отсутствует.
