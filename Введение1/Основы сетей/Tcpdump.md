==🟣Захваченные пакеты==

Во многих случаях вам следует повторно проверить захваченные пакеты позже. Этого можно добиться, сохранив их в файл с помощью команды `-w FILE`

С помощью Tcpdump можно читать пакеты из файла `-r FILE`.

Вы можете указать количество захватываемых пакетов, задав значение счетчика `-c COUNT`. Без указания счетчика захват пакетов будет продолжаться до тех пор, пока вы его не прервете, например, нажав CTRL-C.

Tcpdump разрешает IP-адреса и, по возможности, выводит понятные доменные имена. Чтобы избежать таких DNS-запросов, можно использовать соответствующий `-n`аргумент. ==🟣Фильтрация по хосту==

Вы можете легко ограничить перехват пакетов хостом, используя `host IP`или `host HOSTNAME`.

Если вы хотите ограничить количество пакетов только теми, которые приходят с определенного IP-адреса или имени хоста, необходимо использовать `src host IP`или `src host HOSTNAME`. 
Аналогично, вы можете ограничить количество пакетов только теми, которые отправляются в определенное место назначения, используя `dst host IP`или `dst host HOSTNAME`.

==🟣Фильтрация по порту==

Вы можете ограничить перехват только пакетами, отправленными с определенного номера порта-источника или с определенного номера порта назначения, используя соответственно `src port PORT_NUMBER`и `dst port PORT_NUMBER`.

==🟣Фильтрация по протоколу==

Вы можете ограничить захват пакетов определенным протоколом; например: `ip`, `ip6`,`udp`, `tcp`, и `icmp`.

==🟠Логические операторы==

Три логических оператора, которые могут быть полезны:

- `and`: Захватывает пакеты, в которых выполняются оба условия. Например, `tcpdump host 1.1.1.1 and tcp`захватывает `tcp`трафик с `host 1.1.1.1`.
- `or`: Захватывает пакеты, когда выполняется хотя бы одно из условий. Например, `tcpdump udp or icmp`захватывает UDP или трафик ICMP.
- `not`: Захватывает пакеты, когда условие не выполняется. Например, `tcpdump not tcp`захватывает все пакеты, кроме TCP сегментов; мы ожидаем обнаружить среди результатов пакеты UDP, ICMP и ARP.

==🟣Расширенная фильтрация==

мы можем ограничить отображение только теми пакетами, длина которых меньше или больше определенной:

- `greater LENGTH` Фильтрует пакеты, длина которых больше или равна указанной длине.
- `less LENGTH` Фильтрует пакеты, длина которых меньше или равна указанной длине.

==🟠Бинарные операции==

 Бинарная операция работает с битами, то есть с нулями и единицами. Операция принимает один или два бита и возвращает один бит.
 
- `&`Функция (And) принимает два бита и возвращает 0, если оба входных значения не равны 1
- `|`(Или) принимает два бита и возвращает 1, если оба входных значения не равны 0.
- `!`(Не) принимает один бит и инвертирует его; на вход 1 подается 0, а на вход 0 подается 1

==🟣Байты заголовка==

Используя pcap-filter, Tcpdump позволяет обращаться к содержимому любого байта в заголовке, используя следующий синтаксис `proto[expr:size]`, где:

- `proto`обозначает протокол. Например, `arp`, `ether`, `icmp`, `ip`, `ip6`, `tcp`, и `udp`относятся к ARP, Ethernet, ICMP, IPv4, IPv6, TCP и UDP соответственно.
- `expr`обозначает смещение в байтах, где `0`относится к первому байту.
- `size`указывает количество интересующих нас байтов, которое может быть одним, двумя или четырьмя. Это необязательный параметр, по умолчанию равный единице.

Вы можете использовать `tcp[tcpflags]`для ссылки наTCP Поле флагов. Для сравнения доступны следующие флаги TCP:

- `tcp-syn`TCP SYN (Синхронизация)
- `tcp-ack`TCP ACK (Подтверждение)
- `tcp-fin`TCP FIN (Завершение)
- `tcp-rst`TCP RST (Сброс)
- `tcp-push`TCP Push

Tcpdump — это многофункциональная программа с множеством опций для настройки способа вывода и отображения пакетов.

- `-q`Быстрый вывод; печать краткой информации о пакете.
- `-e`: Вывести заголовок канального уровня
- `-A`: Отображение данных пакета в формате ASCII
- `-xx`Отображение данных пакета в шестнадцатеричном формате, называемом hex.
- `-X`Отображение заголовков и данных пакетов в шестнадцатеричном и ASCII-формате.
