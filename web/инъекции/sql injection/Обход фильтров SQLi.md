[[SQL-injection]]

Для успешной эксплуатации уязвимостей крайне важно уметь обходить фильтры при проведении инъекционных атак. Современные веб-приложения часто используют защитные меры для очистки или блокировки распространенных шаблонов атак, что делает простые попытки SQL-инъекций неэффективными.

==🔵Кодирование символов.==
Кодирование символов включает преобразование специальных символов в полезной нагрузке SQL-инъекции в закодированные формы, которые могут обойти входные фильтры.

- ***Кодирование URL :*** Кодирование URL — это распространенный метод, при котором символы представляются с помощью знака процента (%), за которым следует их значение ASCII в шестнадцатеричном формате. Например, полезная нагрузка ' OR 1=1--может быть закодирована как %27%20OR%201%3D1--. Такое кодирование помогает входным данным пройти через фильтры веб-приложений и быть декодированными базой данных, которая может не распознать их как вредоносные во время первоначальной обработки.
	
- ***Шестнадцатеричное кодирование :*** Шестнадцатеричное кодирование — ещё один эффективный метод построения SQL-запросов с использованием шестнадцатеричных значений. Например, запрос SELECT * FROM users WHERE name = 'admin'можно закодировать как SELECT * FROM users WHERE name = 0x61646d696e. Представляя символы в виде шестнадцатеричных чисел, злоумышленник может обойти фильтры, которые не декодируют эти значения перед обработкой входных данных.
	
- ***Unicode Encoding:*** Кодировка Unicode представляет символы с помощью управляющих последовательностей Unicode. Например, строка adminможет быть закодирована как \u0061\u0064\u006d\u0069\u006e. Этот метод позволяет обойти фильтры, проверяющие только определенные символы ASCII, поскольку база данных корректно обработает закодированные входные данные.

Методы SQL-инъекций без кавычек используются, когда приложение фильтрует одинарные или двойные кавычки или экранирование.

- ***Использование числовых значений :*** Один из подходов заключается в использовании числовых значений или других типов данных, не требующих кавычек. Например, вместо внедрения ' OR '1'='1, злоумышленник может использовать OR 1=1в контексте, где кавычки не нужны. Этот метод может обойти фильтры, которые специально ищут экранирование или удаляют кавычки, позволяя осуществить внедрение.
	
- ***Использование комментариев SQL*** : Другой метод предполагает использование комментариев SQL для завершения оставшейся части запроса. Например, входные данные admin'--можно преобразовать в формат admin--, где --обозначает начало комментария в SQL, фактически игнорируя оставшуюся часть оператора SQL. Это может помочь обойти фильтры и предотвратить синтаксические ошибки.
	
- ***Использование функции CONCAT()*** : Злоумышленники могут использовать функции SQL, например, CONCAT() для создания строк без кавычек. Например, функция CONCAT(0x61, 0x64, 0x6d, 0x69, 0x6e) создает строку "admin". CONCAT() Функция и аналогичные методы позволяют злоумышленникам создавать строки без прямого использования кавычек, что затрудняет обнаружение и блокировку вредоносного кода фильтрами.

Когда использование пробелов запрещено или они отфильтрованы, для обхода этого ограничения можно использовать различные методы.

- ***Комментарии для замены пробелов :*** Один из распространенных методов — использование комментариев SQL ( \/\*\*\/) для замены пробелов. Например, вместо SELECT * FROM users WHERE name = 'admin', злоумышленник может использовать SELECT/\*\*/ \*FROM/\*\*/users/\*\*/WHERE/\*\*/name/\*\*/='admin'. Комментарии SQL могут заменять пробелы в запросе, позволяя вредоносной программе обходить фильтры, удаляющие или блокирующие пробелы.
- ***Символы табуляции или новой строки :*** Другой подход заключается в использовании символов табуляции ( \t) или новой строки ( \n) в качестве замены пробелов. Некоторые фильтры могут допускать эти символы, что позволяет злоумышленнику составить запрос, например SELECT\t*\tFROM\tusers\tWHERE\tname\t=\t'admin', . Этот метод может обойти фильтры, которые специально ищут пробелы.
- ***Альтернативные символы :*** Один из эффективных методов — использование альтернативных символов, закодированных в URL, представляющих различные типы пробелов, такие как %09(горизонтальная табуляция), %0A (перевод строки), %0C (перевод формы), %0D(возврат каретки) и %A0(неразрывный пробел). Эти символы могут заменять пробелы в полезной нагрузке.
