[[SSTI]]

Jinja2 — популярный шаблонизатор для Python, известный своей гибкостью и производительностью. Он широко используется в веб-приложениях для рендеринга динамического контента, поскольку позволяет встраивать выражения, подобные тем, что используются в Python, в HTML. Хотя Jinja2 ускоряет разработку и облегчает разделение представления и бизнес-логики, его мощные возможности шаблонизации могут также представлять значительные риски для безопасности, если ими не управлять должным образом.

Поскольку Jinja2 позволяет выполнять выражения Python внутри шаблонов, риск безопасности в Jinja2 часто возникает из-за небезопасных методов кодирования, которые позволяют выполнять ввод данных пользователем внутри шаблонов без надлежащей проверки. Уязвимость не присуща самой Jinja2, а скорее тому, как разработчики обрабатывают ввод данных пользователем в своих шаблонах. Надлежащая проверка и валидация всех пользовательских данных перед их включением в шаблоны крайне важны для предотвращения подобных проблем безопасности.

Ключевые уязвимые места:

- ***Оценка выражений :*** Jinja2 оценивает выражения внутри фигурных скобок {{ }}, что может привести к выполнению произвольного кода Python, если он составлен злонамеренно.
	
- ***Наследование шаблонов и импорт*** : Расширенные функции, такие как наследование шаблонов и импорт макросов, могут быть использованы не по назначению для выполнения непредусмотренного кода, что может привести к раскрытию информации или манипулированию сервером.

Пример полезной нагрузки:
`{{"".__class__.__mro__[1].__subclasses__()[157].__repr__.__globals__.get("__builtins__").get("__import__")("subprocess").check_output("ls")}}`

Ниже приведено описание указанной полезной нагрузки:

- "".\_\_class\_\_.\_\_mro_\_\[1] Обращается к базовому objectклассу, суперклассу всех классов Python.
- \_\_subclasses\_\_(): Отображает все подклассы класса object и \[157] обычно является индексом класса subprocess.
- Popen (этот индекс может меняться и должен быть проверен в целевой среде).
- Последующие цепочки методов динамически импортируют и используют subprocess модуль для выполнения ls команды, захватывая её вывод.

`check_output` функция предназначена для повышения безопасности за счет отделения команды от ее аргументов, что помогает предотвратить атаки с внедрением командной оболочки. 
Вот общий синтаксис:
`subprocess.check_output([command, arg1, arg2])`

команда : Строка, указывающая команду для выполнения.
arg1, arg2, ... : Дополнительные аргументы, которые должны быть переданы команде.

==🔴Исправления==

1. Включите изолированную среду в Jinja2, чтобы ограничить доступ шаблона к небезопасным функциям и атрибутам. Это предотвратит выполнение произвольного кода Python. Например:
```
from jinja2 import Environment, select_autoescape, sandbox

env = Environment(
    autoescape=select_autoescape(['html', 'xml']),
    extensions=[sandbox.SandboxedEnvironment]
)
```
2. Всегда очищайте входные данные, экранируя или удаляя потенциально опасные символы и строки, которые могут быть интерпретированы как код. Это крайне важно, когда входные данные используются непосредственно в шаблонных выражениях.
3. Регулярно проверяйте и проверяйте шаблоны на наличие небезопасных шаблонов кодирования, например, непосредственно на наличие уязвимостей. Ввод данных пользователем без предварительной проверки.
