[[SSTI]]

Pug (ранее известный как Jade) — это высокопроизводительный шаблонизатор, широко используемый в сообществе Node.js благодаря лаконичному рендерингу HTML и расширенным функциям, таким как условные операторы, итерации и наследование шаблонов. Хотя Pug предоставляет разработчикам мощные инструменты, его способность выполнять код JavaScript непосредственно внутри шаблонов может представлять значительные риски для безопасности.

Уязвимости Pug в системе безопасности в основном связаны с его способностью встраивать код JavaScript в переменные шаблона. Эта функция, разработанная для генерации динамического контента, может быть использована злоумышленниками, если пользовательский ввод встраивается в шаблон без надлежащей проверки.

Ключевые уязвимые места:

- ***Интерполяция JavaScript*** : Pug позволяет встраивание. Использование JavaScript непосредственно в шаблонах с помощью интерполяционных фигурных скобок #{}. Если пользовательский ввод интерполируется без надлежащей проверки, это может привести к выполнению произвольного кода.
- ***Экранирование по умолчанию*** : Pug обеспечивает автоматическое экранирование для некоторых входных данных, преобразуя такие символы, как <, >, и & в их эквиваленты HTML-сущностей для предотвращения XSS-атак. Однако это поведение по умолчанию не охватывает все потенциальные проблемы безопасности, особенно при работе с неэкранированной интерполяцией !{}или сложными сценариями ввода.

Поскольку Pug поддерживает интерполяцию JavaScript, мы можем использовать полезную нагрузку.
`#{root.process.mainModule.require('child_process').spawnSync('ls').stdout}`

Приведенная выше полезная нагрузка использует основные модули Node.js для выполнения системных команд. Ниже приведено подробное описание:

- root.process Обращается к глобальному processобъекту из Node.js внутри шаблона Pug.
- mainModule.require('child_process') Модуль подключается динамически child_process, обходя потенциальные ограничения, которые могли бы помешать его регулярному включению.
- spawnSync('ls'): Выполняет ls команду синхронно.
- .stdout: Захватывает стандартный вывод команды, включая список файлов в каталоге.

Эта `spawnSync` функция предназначена для выполнения команды в командной оболочке и обеспечения детального контроля над вводом и выводом команды. Она является частью `child_process` модуля Node.js, который позволяет Node.js запускать другие процессы в системе, где он работает.

Сигнатура функции spawnSyncвыглядит следующим образом:

`spawnSync(command, [args], [options])`

- команда : Это строка, указывающая команду для выполнения.
- args : Это массив строковых аргументов, которые будут переданы команде.
- options : Это необязательный параметр, который может указывать различные параметры, такие как рабочий каталог, переменные среды, ввод, вывод, тайм-аут и многое другое.

==🔴Исправления==

1. Избегайте прямой оценки JavaScript : ограничьте или избегайте использования возможности Pug оценивать код JavaScript внутри шаблонов. Используйте альтернативные методы обработки динамического контента, которые не предполагают прямого выполнения кода. Например:
```
var user = !{JSON.stringify(user)}
h1= user.name
```
Используйте !{} с осторожностью, так как это позволяет получать неэкранированный вывод, что может быть опасно. Предпочитайте вариант #{}, который экранирует HTML по умолчанию.
2. Проверка и очистка входных данных : Убедитесь, что все пользовательские данные проверяются на соответствие строгой схеме и очищаются перед тем, как они будут отображены шаблонизатором. Это снижает риск выполнения вредоносного кода.
3. Безопасные параметры конфигурации : используйте параметры среды и настройки конфигурации, которые минимизируют риски, например, отключите любые функции, разрешающие выполнение скриптов.
