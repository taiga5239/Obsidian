[[A05 Injection]]

Внедрение команд может называться «удалённым выполнением кода» Remote Code Execution RCE. Эти два понятия связаны, но различны. **RCE** описывает более широкое последствие, когда злоумышленник получает возможность выполнять код на удаленной системе. Внедрение команд — один из конкретных методов достижения этого результата. Другие методы, такие как небезопасная десериализация или повреждение памяти, также могут привести к RCE.

Внедрение команд ОС конкретно соответствует **CWE-78** ( _Неправильная нейтрализация специальных элементов, используемых в команде ОС_ ). Хотя внедрение команд ОС опустилось на несколько позиций по сравнению с предыдущими версиями списка, оно остается одним из наиболее широко тестируемых и используемых классов уязвимостей.

Внедрение команд существует потому, что многие языки программирования предоставляют встроенные функции, позволяющие коду приложения выполнять команды непосредственно в базовой операционной системе. PHP имеет `exec()`, `system()`, `shell_exec()`, и `passthru()`. В Python есть `subprocess`модуль . В Node.js есть `child_process.exec()`. Сами по себе эти функции не опасны. Однако они становятся серьезной проблемой, когда в них передается ввод, предоставленный пользователем, без какой-либо проверки или очистки.

Приведенное ниже PHP-приложение позволяет пользователю искать название песни в текстовом файле, хранящемся на сервере.
```php
<?php
$songs = "/var/www/html/songs";                                    // 1

if (isset($_GET["title"])) {
    $title = $_GET["title"];                                       // 2

    $command = "grep $title /var/www/html/songtitle.txt";          // 3

    $search = exec($command);                                      // 4
    if ($search == "") {
        $return = "<p>The requested song</p><p> $title does </p><b>not</b><p> exist!</p>";
    } else {
        $return = "<p>The requested song</p><p> $title does </p><b>exist!</b>";
    }

    echo $return;
}
?>
```

Обычный поиск, например, `?title=Yesterday`выдает команду `grep Yesterday /var/www/html/songtitle.txt`, которая совершенно безвредна. Однако злоумышленник может `?title=; cat /etc/passwd`вместо этого ввести другую команду. В результате получится следующая команда:

```bash
grep ; cat /etc/passwd /var/www/html/songtitle.txt
```

Эта проблема не является специфичной для PHP. Она может возникнуть в любом языке, позволяющем приложениям выполнять системные вызовы. В следующем примере используется веб-фреймворк Flask на Python.

```python
import subprocess
from flask import Flask                                            # 1
app = Flask(__name__)

def execute_command(shell):                                        # 2
    return subprocess.Popen(shell, shell=True, stdout=subprocess.PIPE).stdout.read()

@app.route('/<shell>')                                             # 3
def command_server(shell):
    return execute_command(shell)
```

При внедрении команд **с ==🟣подробным** выводом== приложение отображает результат внедренной команды непосредственно в своем ответе. Если злоумышленник внедряет команду `; whoami`в уязвимое поле ввода, имя пользователя, от имени которого запущено приложение, может отображаться на странице рядом с обычным выводом. С этим методом работать проще, поскольку результат внедрения виден сразу.

==🟣**Слепое** внедрение== команд обнаружить сложнее. Команда по-прежнему выполняется на сервере, но приложение не возвращает с него никакого результата. Страница может выглядеть идентично независимо от того, удалось внедрение или нет. В этом случае вам придется полагаться на косвенные сигналы, чтобы подтвердить выполнение команды.

Поскольку результат внедренных команд невидим, приходится полагаться на наблюдаемые побочные эффекты. Наиболее распространенный подход — использование полезных нагрузок, вызывающих **задержку по времени** .

Команды `ping` and `sleep` особенно полезны для этой цели. Внедрение команды `; ping -c 10 127.0.0.1`в уязвимое поле ввода должно привести к увеличению времени ответа приложения примерно на 10 секунд. Если время ответа увеличивается пропорционально количеству указанных запросов, это является убедительным признаком успешного внедрения команды.

Другой метод заключается в **принудительной записи вывода в файл** с помощью операторов перенаправления.

Эта `curl`команда — ещё один полезный инструмент для тестирования внедрения команд. Она позволяет создавать и отправлять запросы к уязвимому приложению с внедренными полезными нагрузками, встроенными в URL. Следующая полезная нагрузка добавляется `; whoami`к `search`параметру уязвимого приложения:

```bash
curl http://vulnerable.app/process.php%3Fsearch%3DThe%20Beatles%3B%20whoami
```

Netcat можно использовать для запуска обратной оболочки в уязвимом приложении, обеспечивая интерактивный доступ для исследования системы и поиска путей повышения привилегий.

==🔴Исправление==

В PHP существует несколько функций, взаимодействующих с операционной системой для выполнения команд через оболочку. К ним относятся `exec()`, `passthru()`, и `system()`. Эти функции принимают на вход такие данные, как строка или пользовательские данные, и выполняют всё, что предоставлено системой. Любое приложение, использующее эти функции без надлежащей проверки, будет уязвимо для внедрения команд.

Один из способов снизить риск — ограничить тип данных, которые приложение принимает изначально.

Это хорошая первая линия защиты, но она не должна быть единственной. Клиентская валидация, например, проверка HTML-шаблонов, может быть обойдена злоумышленником, отправляющим запросы напрямую (например, с помощью `curl`Burp Suite), поэтому проверка на стороне сервера крайне важна.

==🔴Очистка входных данных==

Проверка пользовательского ввода на стороне сервера — один из наиболее эффективных способов предотвращения внедрения команд. Это означает указание точных форматов или типов данных, которые пользователю разрешено отправлять, и отклонение всего остального. Например, поле ввода может принимать только числовые данные, или приложение может удалять специальные символы, такие как `>`, `&`, и `/`перед обработкой ввода.

==🔴Обход фильтров==

Важно понимать, что фильтры не всегда абсолютно надежны. Приложения используют различные методы для очистки пользовательского ввода, и эти фильтры могут ограничивать доступ к определенным вредоносным программам. Однако злоумышленник иногда может использовать уязвимость в базовой логике приложения, чтобы обойти их.

Например, приложение может удалять кавычки или определенные символы из пользовательского ввода. В этом случае злоумышленник может представить ту же строку, используя ее шестнадцатеричную кодировку:

```php
$payload = "\x2f\x65\x74\x63\x2f\x70\x61\x73\x73\x77\x64"
```

Эта строка в шестнадцатеричном коде декодируется как `/etc/passwd`. Когда приложение обрабатывает её, данные поступают в другом формате, чем тот, который ожидает фильтр, но система всё равно интерпретирует их правильно и выдаёт тот же результат. Фильтр видит шестнадцатеричные значения и пропускает их, но операционная система считывает их `/etc/passwd`и действует соответствующим образом.

Вот почему важна многоуровневая защита. Ни один отдельный уровень защиты не гарантирует обнаружения всего. Сочетание проверки входных данных, очистки, внесения в список разрешенных и принципа минимальных привилегий дает наилучшие шансы предотвратить внедрение команд, даже если один уровень защиты будет обойден.
